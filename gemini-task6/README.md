# День 6. Первый агент

Самостоятельный AI-агент на Gemini API (`gemini-3.5-flash-lite`, `google-genai` 2.34.0) с тремя инструментами
и **собственным циклом Function Calling**. Модель сама решает, нужен ли инструмент, и выбирает аргументы.
Python выполняет функции и возвращает результаты модели, а цикл повторяется до финального текстового ответа.

## Структура

```
gemini-task6/
├── main.py        # CLI-чат, тестовые сценарии (--scenarios), --dry-run, --check-model
├── agent.py       # класс Agent: история, цикл Function Calling, ошибки, логирование
├── tools.py       # 3 Python-функции, FunctionDeclaration (JSON Schema), диспетчер dispatch()
├── config.py      # модель, лимиты, системная инструкция, курс, таймауты, тарифы
├── tests/
│   ├── fakes.py                  # фейковый клиент Gemini (сценарные ответы)
│   ├── test_tools.py             # инструменты и диспетчер
│   ├── test_agent.py             # цикл агента: 0/1/2 инструмента, ошибки, лимит итераций
│   ├── test_sdk_wire.py          # настоящий genai.Client + httpx.MockTransport (без сети)
│   └── test_main_and_secrets.py  # проверки сценариев, поиск ключа в файлах, фильтр логов
├── results/       # JSON с прогонами сценариев (появляется после --scenarios)
├── README.md
└── .gitignore
```

## Инструменты

| Инструмент | Параметры | Что делает |
|---|---|---|
| `get_current_time` | — | дата, время, день недели в `Asia/Ho_Chi_Minh` (UTC+7) |
| `calculate` | `expression: string` | арифметика через `ast` по белому списку: числа, скобки, `+ - * / // % **`. `eval` не используется. Есть ограничения: длина ≤ 200, степень ≤ 100, \|результат\| ≤ 1e30, деление на ноль даёт ошибку |
| `convert_currency` | `amount: number`, `from_currency`, `to_currency` (`enum: USD, VND`) | конвертация по **фиксированному демо-курсу 1 USD = 25 000 VND**. В ответе есть `rate_is_fixed_demo: true` и `note`: «это НЕ актуальный рыночный курс» |

Схемы передаются модели как `types.FunctionDeclaration` с `parameters_json_schema` (JSON Schema).
`dispatch(name, args)` находит функцию в реестре `TOOL_FUNCTIONS` и сверяет аргументы со схемой и
сигнатурой. Ответ всегда `{"result": ...}` или `{"error": ...}`, исключения наружу не выходят.
Поэтому модель видит ошибку и может исправить аргументы.

## Архитектура агента

```
Пользователь ─► main.py (CLI) ─► Agent.run(message)
                                    │
             ┌──────────────────────┴───────────────────────────┐
             │ history += user                                  │
             │ for iteration in 1..MAX_ITERATIONS (10):         │
             │   resp = client.models.generate_content(         │
             │            history, tools=FunctionDeclarations,  │
             │            automatic_function_calling.disable)   │
             │   history += resp.candidates[0].content  (как есть)
             │   нет function_call? ──► return текст (ok)       │
             │   для каждого function_call:                     │
             │       tools.dispatch(name, args)  ← Python       │
             │       FunctionResponse(id, name, response)       │
             │   history += user(все FunctionResponse хода)     │
             │ лимит исчерпан ──► return max_iterations         │
             └──────────────────────────────────────────────────┘
```

**Где цикл:** `agent.py`, метод `Agent.run()`, строка `for iteration in range(1, self.max_iterations + 1)`.
Шаги 1–8 задания помечены в коде комментариями.

Почему это ручной Function Calling:
- в `tools=` передаются только `FunctionDeclaration`, а не Python-функции. SDK нечего выполнять;
- дополнительно задано `AutomaticFunctionCallingConfig(disable=True)`;
- `FunctionCallingConfig(mode=AUTO)`: модель сама решает, вызывать ли инструмент.

**История и thought signatures.** Gemini 3 прикладывает к частям ответа (в том числе к `functionCall`)
непрозрачную `thought_signature`. Без неё модель не может продолжить рассуждение после вызова функции.
Агент кладёт в историю `candidate.content` **целиком, без пересборки**, поэтому подписи, текст рядом
с вызовом и порядок частей сохраняются. Ответы на все вызовы одного хода отправляются одним
сообщением `role="user"` в том же порядке. `FunctionResponse.id` совпадает с `FunctionCall.id`.
`test_sdk_wire.py` проверяет, что `thoughtSignature` и `functionResponse.id` реально уходят в HTTP-запрос.

**Ошибки.**
- Ошибка инструмента: передаётся модели как `{"error": ...}`, цикл продолжается.
- Ошибка API / сети: статус `api_error`, понятное сообщение пользователю.
  Временные ошибки (429, 5xx) повторяет сам SDK (`HttpRetryOptions`, 3 попытки).
- Пустой ответ (например, `SAFETY`): статус `empty_response`.
- Лимит итераций: статус `max_iterations`.
- При любом неуспехе история **откатывается** к состоянию до запроса. В ней не остаётся
  оборванных `function_call` без ответа, и следующий запрос чата работает.

**Логирование** (`logging`, логгер `agent`): номер итерации, имя инструмента, аргументы (JSON),
результат или ошибка, итог. `--log-file` дублирует лог в `logs/` (папка в `.gitignore`).
`RedactSecretsFilter` и `redact_secrets()` заменяют значение ключа на `***`, если оно случайно попадёт
в текст ошибки.

## Запуск

```bash
cd ~/work/AICourse/gemini-task6
export GEMINI_API_KEY=...            # ключ только в окружении, не в файлах

../venv/bin/python main.py --dry-run       # без API: настройки, схемы, сценарии
../venv/bin/python main.py --check-model   # бесплатно: метаданные модели (без генерации)
../venv/bin/python main.py                 # чат (каждый запрос — платные вызовы)
../venv/bin/python main.py --verbose --log-file
```

В чате: `exit` (`quit`, `выход`) завершает работу, `reset` очищает историю.

### С реальным API (платно, нужен отдельный запуск)

```bash
../venv/bin/python main.py --scenarios          # все три; перед запуском спросит подтверждение
../venv/bin/python main.py --scenarios 3        # только третий
```

| № | Запрос | Ожидается |
|---|---|---|
| 1 | «Объясни простыми словами, что такое API» | ответ без вызовов инструментов, 1 запрос к модели |
| 2 | «Сколько будет 150 долларов в донгах?» | `convert_currency(150, USD, VND)` → 3 750 000 VND и пометка о фиксированном курсе |
| 3 | «Переведи 150 долларов в донги, а затем рассчитай, сколько получится, если добавить к этой сумме ещё 10 процентов» | ход 1: `convert_currency` → 3 750 000; ход 2: `calculate("3750000 * 1.1")` → 4 125 000; ход 3: финальный текст |

Скрипт **не подсказывает** модели инструменты. Ожидаемая последовательность используется только
для автоматической проверки после ответа (`check_scenario` в `main.py`):
- совпадают имена и порядок успешных вызовов;
- в сценарии 3 `calculate` вызван в **следующем** ходе после конвертации, а его выражение содержит
  полученное число 3750000;
- в ответе есть итоговое число;
- если была конвертация, ответ упоминает, что курс фиксированный.

Протокол прогона сохраняется в `results/scenarios_<дата>.json`: вызовы, аргументы, ответы инструментов,
итоговый текст, токены.

Стоимость: около 6 вызовов `generate_content` по несколько сотен токенов, то есть доли цента
по тарифу $0.30 / $2.50 за 1M токенов (input / output). У модели есть бесплатный уровень.
Оценка сверху при срабатывании лимита во всех сценариях: ≈ $0.18.

## Ограничения

- Курс USD/VND демонстрационный и захардкожен (`config.USD_TO_VND_RATE`).
- `calculate` не знает переменных, функций и `%` как процента. Модели об этом сказано в описании инструмента.
- При ошибке запрос откатывается из истории целиком, и контекст неудачного запроса теряется.
- История хранится только в памяти процесса.
