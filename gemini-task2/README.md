# Задача №2: три способа запроса к Gemini API

Один и тот же запрос отправляется в модель `gemini-3.8-flash` тремя способами, каждый вариант запускается 3 раза.

**Запрос:** «Порекомендуй 3 книги по программированию для начинающих. Для каждой укажи название, автора, год издания и коротко объясни, почему её стоит прочитать.»

| Вариант | Что меняется |
|---|---|
| `v1_unconstrained` | Только базовый запрос, без конфига |
| `v2_format_and_limits` | К запросу добавлено текстовое описание JSON-формата; `max_output_tokens=400`, `stop_sequences=["<<END>>"]` |
| `v3_structured_output` | Базовый запрос; `response_mime_type="application/json"`, `response_schema=ApiBookRecommendations` (Pydantic) |

## Файлы

- `config.py` — модель, промпт, Pydantic-схемы, параметры вариантов, таймаут и повторы:
  - `ApiBook` / `ApiBookRecommendations` — схема для `response_schema` (ровно 3 книги, без `extra="forbid"`: Gemini API не принимает `additionalProperties`);
  - `StrictBook` / `StrictBookRecommendations` — те же поля и ограничения + запрет лишних полей; ими проверяются ответы всех трёх вариантов.
- `experiment.py` — запуск эксперимента, проверки, сохранение результатов; аргумент `--model` для запасной модели.
- `offline_checks.py` — офлайн-проверки (сеть заблокирована, клиент API — заглушка).
- `results/raw_results.json`, `results/summary.md` — результаты основной модели (`gemini-3.8-flash`).
- `results/model_<имя>/` — результаты запасной модели, например `results/model_gemini-3.6-flash/`.
- `results/run_1_failed/`, `results/run_2_failed/` — неудачные прогоны, сохранены без изменений (см. «История прогонов»).

## Проверки (одинаковые для всех вариантов)

1. **Парсинг JSON** — строгий `json.loads` по тексту ответа. Markdown-обёртка ```` ```json ```` не снимается и считается ошибкой парсинга (отдельно отмечается флагом `has_code_fence`). Статусы: `ok`, `empty`, `json_error`.
2. **Валидация Pydantic** — `StrictBookRecommendations.model_validate(...)`: объект с ключом `books`, ровно 3 элемента, у каждого `title`, `author`, `reason` — непустые строки, `year` — целое число, лишние поля запрещены. Статусы: `ok`, `validation_error`, `skipped` (если JSON не распарсился).

Ошибки парсинга, ошибки валидации и ошибки API фиксируются раздельно.

## Таймаут и повторные попытки

Таймаут одного запроса — 120 с. При ошибке API 503 или 504 запрос повторяется один раз через 13 с (до 2 попыток на запуск; максимум 18 запросов за прогон при дневном лимите бесплатного тарифа 20). Между запусками пауза 13 с: бесплатный тариф допускает 5 запросов в минуту, и попытки с ошибкой 503 тоже засчитываются. Каждая попытка записывается в `attempts` в `raw_results.json`; в сводке видно число попыток на запуск и итоговый результат.

Варианты чередуются: v1, v2, v3, v1, v2, v3, … — чтобы перегрузка или исчерпание квоты затрагивали все варианты одинаково. При первой ошибке 429 (квота) эксперимент немедленно останавливается; невыполненные запуски перечисляются в сводке. `raw_results.json` и `summary.md` сохраняются после каждого запуска. Если в `results/` уже лежат результаты, скрипт откажется запускаться, чтобы их не перезаписать.

## История прогонов

- `results/run_1_failed/` — 03.11: v1/v2 — 503/504 (перегрузка модели), v3 — 400 `additional_properties` в схеме.
- `results/run_2_failed/` — 04.11: 503/504 при повторах, затем 429 (исчерпан дневной лимит 20 запросов).
- `results/raw_results.json`, `results/summary.md` — 04.11, 22:08: третий прогон, остановлен после 5 из 9 запусков: 8 попыток с 503, затем 429 по **поминутному** лимиту (`requests per minute`, limit: 5).

## Что сохраняется для каждого запуска

Промпт и конфиг запроса, время ответа, `finish_reason`, `usage_metadata` целиком (включая `thoughts_token_count`, если есть), полный исходный текст ответа, его длина, результаты обеих проверок.

## Запуск

```bash
export GEMINI_API_KEY="ваш_ключ"
../venv/bin/python experiment.py --dry-run   # показать запросы, без обращения к API
../venv/bin/python experiment.py             # 9 запусков на gemini-3.8-flash
../venv/bin/python offline_checks.py         # офлайн-проверки, без обращения к API
```

## Запасная модель

`gemini-3.8-flash` в дни эксперимента была перегружена (503/504), а квота бесплатного тарифа заканчивалась (429). Поэтому эксперимент можно повторить на другой модели — с теми же промптами, конфигами, схемами и проверками:

```bash
../venv/bin/python experiment.py --model gemini-3.6-flash --dry-run
../venv/bin/python experiment.py --model gemini-3.6-flash        # основная запасная
../venv/bin/python experiment.py --model gemini-3.5-flash-lite   # резервная
```

- `MODEL` в `config.py` не меняется; без `--model` используется `gemini-3.8-flash`.
- Результаты другой модели пишутся в `results/model_<имя>/` и не смешиваются с результатами `gemini-3.8-flash`.
- Квота бесплатного тарифа считается отдельно для каждой модели.
- Результаты на другой модели нельзя напрямую сравнивать с задачей №1: модель отличается.
