# День 8. Работа с токенами

Самостоятельный AI-агент на Gemini API (`gemini-3.5-flash-lite`, `google-genai` 2.34.0) с тремя инструментами
и **собственным циклом Function Calling**. Модель сама решает, нужен ли инструмент, и выбирает аргументы.
Python выполняет функции и возвращает результаты модели, а цикл повторяется до финального текстового ответа.

**День 7:** история диалога целиком (включая вызовы инструментов и их результаты) сохраняется в
`results/chat_history.json` и загружается при перезапуске, так что диалог продолжается, как будто агент
не выключался. Подробности — в разделе «История диалога между перезапусками».

**День 8:** агент считает токены. Перед каждым обращением к модели он считает текущее сообщение и всю
историю (вместе с `function_call` / `function_response`) официальным методом `client.models.count_tokens`.
Фактический расход каждого обращения берётся из `response.usage_metadata`. После каждого хода печатается
статистика и примерная стоимость. Есть три эксперимента: короткий диалог, длинный диалог и переполнение
контекста. Подробности — в разделе «Работа с токенами».

## Инструменты

| Инструмент | Параметры | Что делает |
|---|---|---|
| `get_current_time` | — | дата, время, день недели в `Asia/Ho_Chi_Minh` (UTC+7) |
| `calculate` | `expression: string` | арифметика через `ast` по белому списку: числа, скобки, `+ - * / // % **`. `eval` не используется. Есть ограничения: длина ≤ 200, степень ≤ 100, \|результат\| ≤ 1e30, деление на ноль даёт ошибку |
| `convert_currency` | `amount: number`, `from_currency`, `to_currency` (`enum: USD, VND`) | конвертация по **фиксированному демо-курсу 1 USD = 25 000 VND**. В ответе есть `rate_is_fixed_demo: true` и `note`: «это НЕ актуальный рыночный курс» |

Схемы передаются модели как `types.FunctionDeclaration` с `parameters_json_schema` (JSON Schema).
`dispatch(name, args)` находит функцию в реестре `TOOL_FUNCTIONS` и сверяет аргументы со схемой и
сигнатурой. Ответ всегда `{"result": ...}` или `{"error": ...}`, исключения наружу не выходят.
Поэтому модель видит ошибку и может исправить аргументы.

## Архитектура агента

```
Пользователь ─► main.py (CLI) ─► Agent.run(message)
                                    │
             ┌──────────────────────┴───────────────────────────┐
             │ history += user                                  │
             │ for iteration in 1..MAX_ITERATIONS (10):         │
             │   resp = client.models.generate_content(         │
             │            history, tools=FunctionDeclarations,  │
             │            automatic_function_calling.disable)   │
             │   history += resp.candidates[0].content  (как есть)
             │   нет function_call? ──► return текст (ok)       │
             │   для каждого function_call:                     │
             │       tools.dispatch(name, args)  ← Python       │
             │       FunctionResponse(id, name, response)       │
             │   history += user(все FunctionResponse хода)     │
             │ лимит исчерпан ──► return max_iterations         │
             └──────────────────────────────────────────────────┘
```

**Где цикл:** `agent.py`, метод `Agent.run()`, строка `for iteration in range(1, self.max_iterations + 1)`.
Шаги 1–8 задания помечены в коде комментариями.

Почему это ручной Function Calling:
- в `tools=` передаются только `FunctionDeclaration`, а не Python-функции. SDK нечего выполнять;
- дополнительно задано `AutomaticFunctionCallingConfig(disable=True)`;
- `FunctionCallingConfig(mode=AUTO)`: модель сама решает, вызывать ли инструмент.

**История и thought signatures.** Gemini 3 прикладывает к частям ответа (в том числе к `functionCall`)
непрозрачную `thought_signature`. Без неё модель не может продолжить рассуждение после вызова функции.
Агент кладёт в историю `candidate.content` **целиком, без пересборки**, поэтому подписи, текст рядом
с вызовом и порядок частей сохраняются. Ответы на все вызовы одного хода отправляются одним
сообщением `role="user"` в том же порядке. `FunctionResponse.id` совпадает с `FunctionCall.id`.
`test_sdk_wire.py` проверяет, что `thoughtSignature` и `functionResponse.id` реально уходят в HTTP-запрос.

**Ошибки.**
- Ошибка инструмента: передаётся модели как `{"error": ...}`, цикл продолжается.
- Ошибка API / сети: статус `api_error`, понятное сообщение пользователю.
  Временные ошибки (429, 5xx) повторяет сам SDK (`HttpRetryOptions`, 3 попытки).
- Пустой ответ (например, `SAFETY`): статус `empty_response`.
- Лимит итераций: статус `max_iterations`.
- При любом неуспехе история **откатывается** к состоянию до запроса. В ней не остаётся
  оборванных `function_call` без ответа, и следующий запрос чата работает.

**Логирование** (`logging`, логгер `agent`): номер итерации, имя инструмента, аргументы (JSON),
результат или ошибка, итог. `--log-file` дублирует лог в `logs/` (папка в `.gitignore`).
`RedactSecretsFilter` и `redact_secrets()` заменяют значение ключа на `***`, если оно случайно попадёт
в текст ошибки.

## Работа с токенами

### Откуда берутся числа

| Что | Как считается | Когда |
|---|---|---|
| Токены текущего запроса | `client.models.count_tokens(contents=[сообщение])` | до отправки |
| Токены всей истории | `count_tokens(contents=history)`: текст, `function_call`, `function_response`, thought-части | перед **каждым** обращением к модели в ходе |
| Вызовы инструментов и их результаты за ход | `count_tokens` только по сообщениям с `function_call` / `function_response` этого хода | после хода с инструментами |
| Фактический вход обращения | `usage_metadata.prompt_token_count` (+ `tool_use_prompt_token_count`) | после ответа |
| Ответ модели | `usage_metadata.candidates_token_count` + `thoughts_token_count` (thinking оплачивается как output) | после ответа |
| Кэш | `usage_metadata.cached_content_token_count` (показывается отдельно) | после ответа |

Приблизительного подсчёта по символам нет. `count_tokens` — бесплатный метод API.

**Ограничение SDK.** В `google-genai` 2.34.0 в режиме Gemini Developer API (ключ `GEMINI_API_KEY`)
`count_tokens` принимает **только `contents`**. Если передать `CountTokensConfig(system_instruction=…)`,
`tools=…` или `generation_config=…`, SDK выдаёт `ValueError` («only supported in … Agent Platform
mode»): эти поля работают только в Vertex AI. Это проверяет `test_sdk_rejects_system_instruction_in_count_tokens_for_developer_api`.
Поэтому `count_tokens` считает **историю диалога**, а системная инструкция и схемы инструментов попадают
только в `prompt_token_count`. Их размер выводится отдельной строкой «Служебные» как разница
`prompt_token_count − count_tokens(история)`.

**Несколько обращений за ход.** Если модель вызывает инструменты, один запрос пользователя даёт несколько
`generate_content`. Для каждого обращения хранится `CallStats`: история до отправки, её состав, `usage`
и сколько `function_call` вернула модель. `TurnStats` суммирует их за ход, `SessionStats` — за запуск.
Неуспешный ход (ошибка API, лимит итераций) тоже учитывается в сессии, потому что токены уже потрачены.
`reset` очищает историю, но не счётчик сессии.

### Что печатается после каждого хода

```
─── Токены ─────────────────────────────────────────
Запрос пользователя:     14  (count_tokens)
Обращение 1: история 14 ток. (1 сообщ.) → вход 420, ответ 35 (текст/вызовы 20 + thinking 15), вызовов инструментов: 1
Обращение 2: история 79 ток. (3 сообщ., function_call: 1, function_response: 1) → вход 485, ответ 60 (…)
Вызовы инструментов и их результаты в этом ходе: 65 ток. (count_tokens)
Служебные (system instruction + схемы инструментов): 406 = prompt_token_count − count_tokens(история)
История перед отправкой: 79
Ответ модели (финальный): 60
Итого за ход (2 обращ.): вход 905, выход 95 (из них thinking 30)
Контекст (последний вход): 485 / 1 048 576 (0.05%)
Стоимость хода: ≈ $0.000509
Сессия: ходов 1, обращений 2, вход 905, выход 95, ≈ $0.000509
────────────────────────────────────────────────────
```

(Числа в примере иллюстративные; 14 и 65 — реальные значения `count_tokens` из проверки ниже.)

### Лимит контекста

Лимит не захардкожен. При запуске чата и экспериментов он читается из метаданных модели:
`client.models.get(model).input_token_limit` (бесплатно, без генерации; то же печатает `--check-model`).
Если метаданные недоступны, программа пишет «лимит неизвестен», и локальная проверка не выполняется.

Проверка 11.11.2026: `models/gemini-3.5-flash-lite`, `version=3.5-flash-lite-07-2026`,
**`input_token_limit=1048576`**, `output_token_limit=65536`.

Поведение при переполнении:
- **Защита агента** (`config.ENFORCE_CONTEXT_LIMIT = True`, по умолчанию). Если `count_tokens(история)`
  больше лимита, `generate_content` не вызывается. Статус `context_overflow`, история откатывается
  и в файл не сохраняется.
- **Ошибка API.** Если защита выключена (или `count_tokens` недоступен) и API отклоняет запрос
  с HTTP 400 и текстом о превышении числа токенов, агент тоже возвращает `context_overflow`
  с текстом ошибки API и откатывает историю. Следующий запрос работает как обычно.

### Стоимость

Оценка по `config.PRICING`: для `gemini-3.5-flash-lite` — $0.30 / $2.50 за 1M input / output токенов
(Standard, paid tier, https://aistudio.google.com/docs/pricing, проверено 06.11.2026 в Дне 5).
Thinking оплачивается как output. Кэшированные токены считаются по полной цене (оценка сверху).
Для модели, которой нет в `PRICING`, выводится «тариф неизвестен». На бесплатном уровне
фактическая стоимость $0.

### Эксперименты

Каждый эксперимент использует **отдельного агента в памяти**: `results/chat_history.json` не читается
и не меняется. Перед платными вызовами программа спрашивает подтверждение (`--yes` — без вопроса).
Протокол сохраняется в `results/tokens_<эксперимент>_<дата>.json`.

```bash
cd ~/work/AICourse/gemini-task8
export GEMINI_API_KEY=...

../venv/bin/python main.py --experiment short      # 3 коротких сообщения (~3–4 вызова, доли цента)
../venv/bin/python main.py --experiment long       # 12 сообщений с инструментами (~15–20 вызовов, ≈ центы)
../venv/bin/python main.py --experiment overflow   # вход > input_token_limit
```

1. **Короткий диалог** (`short`): «Привет! Меня зовут Аня.» → «Сколько будет 2 + 2?» → «Как меня зовут?».
   После каждого хода — статистика, в конце — таблица «Рост истории по ходам».
2. **Длинный диалог** (`long`): 12 сообщений: объяснения, `convert_currency`, `calculate`,
   `get_current_time`, резюме. В таблице видно, что «история» растёт с каждым ходом, а «вход за ход»
   растёт быстрее: при каждом обращении вся история отправляется заново, а при вызовах инструментов
   обращений за ход несколько.
3. **Переполнение** (`overflow`):
   1. лимит берётся из `models.get`; если он неизвестен, эксперимент останавливается и сообщает об этом;
   2. собирается текст больше лимита. Его размер **измеряется `count_tokens`**: сначала
      по образцу из 2000 строк, затем по всему тексту. В запуске 11.11.2026: 48 119 строк,
      4 079 005 символов (7 302 978 байт), **1 143 747 токенов — на 95 171 токен (≈ 9,1 %) больше
      лимита 1 048 576**. Код целится в +3 % (`OVERFLOW_MARGIN` в `experiments.py`), но полный текст
      по `count_tokens` оказался «плотнее» образца, а пересчёт строк выполняется, только если текст
      не превысил лимит;
   3. *защита агента*: запрос не уходит в модель (0 вызовов `generate_content`, бесплатно; клиент
      на этом шаге технически не может вызвать генерацию);
   4. после второго подтверждения тот же текст отправляется в `generate_content` с выключенной
      защитой и без повторов SDK. Фиксируется реальный ответ API: код, статус, сообщение;
   5. проверочный короткий запрос показывает, что после ошибки агент работает (история откатилась).

   Отклонённый запрос не должен тарифицироваться. Если API всё же примет вход, `max_output_tokens=16`,
   и худший случай для 1 143 747 токенов ≈ $0.34. На бесплатном уровне вместо 400 возможен 429
   (лимит токенов в минуту): такой результат тоже записывается в протокол как есть. В запуске
   11.11.2026 API вернул 400 `INVALID_ARGUMENT`, `usage_metadata` отсутствовал, стоимость $0.

## История диалога между перезапусками

**Где хранится.** `results/chat_history.json` (путь задаётся в `config.HISTORY_FILE`, переопределяется
флагом `--history-file PATH`). Файл добавлен в `.gitignore`: в нём личная переписка.

**Что хранится.** Полная история Gemini — список `types.Content` в том виде, в каком агент отправляет её
модели: сообщения пользователя, ответы модели, `function_call` (с `id`, `name`, `args`),
`function_response` (с тем же `id`), части с `thought=True` и `thought_signature`. Сериализация — штатная
для pydantic-моделей SDK: `Content.model_dump(mode="json", exclude_none=True)`, восстановление —
`Content.model_validate()`. Бинарная `thought_signature` в JSON записывается как base64 и при загрузке
снова становится `bytes`. История **не** превращается в список текстовых сообщений, поэтому после
перезапуска модель видит ровно тот же контекст, включая сигнатуры, без которых Gemini 3 не продолжит
Function Calling.

```json
{
  "format_version": 1,
  "sdk_version": "2.34.0",
  "saved_at": "2026-11-10T12:00:00",
  "history": [
    {"role": "user", "parts": [{"text": "Сколько будет 150 долларов в донгах?"}]},
    {"role": "model", "parts": [{"function_call": {"id": "…", "name": "convert_currency", "args": {…}},
                                 "thought_signature": "base64…"}]},
    {"role": "user", "parts": [{"function_response": {"id": "…", "name": "convert_currency", "response": {…}}}]},
    {"role": "model", "parts": [{"text": "150 USD = 3 750 000 VND …"}]}
  ]
}
```

API-ключа и конфигурации клиента в файле нет. Если ключ случайно вставлен в текст сообщения,
он заменяется на `***` перед записью (`redact_secrets`).

**Как работает.**
- При запуске чата файл читается автоматически. Нет файла — пустая история. Есть история —
  печатается «Восстановлена история из …: N сообщений».
- После каждого **успешно** завершённого запроса (`status == "ok"`) история записывается атомарно
  (временный файл + `os.replace`), так что сбой во время записи не портит прежний файл.
- Неуспешный запрос (ошибка API, пустой ответ, лимит итераций) агент откатывает, как и раньше,
  поэтому в файл он не попадает. Запрос, прерванный Ctrl+C, тоже убирается из истории.
- `reset` очищает историю в памяти и записывает в файл пустой список — после перезапуска
  старая история не вернётся.
- Если JSON повреждён или несовместим с текущей версией SDK/формата (неверный JSON, чужая версия
  формата, неизвестные SDK поля, неверная роль, битая base64-сигнатура), программа не падает:
  печатает предупреждение с причиной и спрашивает, начать ли с пустой истории.
  «Да» — повреждённый файл переименовывается в `chat_history.corrupted_<дата_время>.json` и
  чат начинается с нуля. «Нет» (или конец ввода) — файл не трогается, программа завершается с кодом 1.

| 2. Защита выключена, запрос в API | `context_overflow` | 1 (отклонён) | `400 INVALID_ARGUMENT: The input token count exceeds the maximum number of tokens allowed (1048576).` | 0 сообщ. | 0 / 0, `usage_metadata` нет | $0 |
| 3. Проверочный запрос | `ok` | 1 | «Да.» | — | 687 / 2 | $0.0002111 |

### Локальная защита и отказ Gemini API: в чём разница

| | Локальная защита агента | Отказ Gemini API |
|---|---|---|
| Где срабатывает | в `Agent`, до `generate_content` | на сервере Google, после отправки |
| Условие | `count_tokens(история) > input_token_limit` | вход (история + служебная часть) больше лимита |
| Сетевой запрос генерации | не отправляется (0 вызовов) | отправляется: ≈ 7.3 МБ текста уходит по сети |
| Ответ | текст агента с точными числами (1143747 / 1048576) | HTTP 400 `INVALID_ARGUMENT` с лимитом, без фактического числа токенов |
| Токены и стоимость | 0 (`count_tokens` бесплатен) | 0: `usage_metadata` отсутствует, вход 0, выход 0 |
| Что делает агент | `context_overflow`, история откатывается | распознаёт ошибку как `context_overflow`, история откатывается |

Итог: оба пути завершаются одинаково для пользователя (`context_overflow`, понятное сообщение,
история не испорчена). Локальная защита срабатывает раньше и ничего не отправляет: не тратит
время и трафик на загрузку мегабайтов, не зависит от формулировки ошибки API, а сообщение у неё
точнее. Отказ API — запасной вариант на случай, когда защита выключена, `count_tokens` недоступен или
превышение меньше служебной части (676 токенов не входят в локальную проверку — см. «Ограничения»).
Отклонённый запрос в этом запуске не тарифицировался.

## Ограничения

- Курс USD/VND демонстрационный и захардкожен (`config.USD_TO_VND_RATE`).
- `calculate` не знает переменных, функций и `%` как процента. Модели об этом сказано в описании инструмента.
- При ошибке запрос откатывается из истории целиком, и контекст неудачного запроса теряется.
- История сохраняется в `results/chat_history.json` целиком и не обрезается: в очень длинном диалоге
  растут контекст и цена каждого запроса. Начать заново — команда `reset`. Агент не сокращает историю
  автоматически: при переполнении он отказывает (`context_overflow`), а не обрезает контекст.
- `count_tokens` в Developer API не учитывает system instruction и схемы инструментов (ограничение SDK);
  они видны только в `prompt_token_count` после ответа. Локальная защита сравнивает с лимитом историю
  без этих служебных токенов, поэтому вход, превышающий лимит лишь на величину служебных токенов
  (сотни), отклонит уже сам API — агент обработает и эту ошибку.
- Подсчёт добавляет 1 бесплатный вызов `count_tokens` на обращение к модели (+1 на запрос и +1 на ход
  с инструментами) — небольшая задержка. Отключается `config.COUNT_TOKENS = False`.
- Стоимость — оценка по тарифу paid tier, без учёта скидки за кэш.
- Файл истории привязан к формату `google-genai`: если новая версия SDK изменит модели, загрузка
  сообщит о несовместимости и предложит начать с пустой истории (старый файл сохранится).
