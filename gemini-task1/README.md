# День 1. Первый запрос к LLM через API

Минимальный Python-скрипт: отправляет текстовый запрос в Gemini API, получает ответ и выводит его в консоль.

- SDK: `google-genai` (как в заданиях `gemini-task2`–`gemini-task5`)
- Модель: `gemini-3.5-flash-lite` (недорогая, есть бесплатный уровень)
- Ключ: переменная окружения `GEMINI_API_KEY`, загружается из файла `.env`

## Файлы

| Файл | Назначение |
|------|------------|
| `main.py` | Скрипт: загрузка `.env`, запрос к модели, вывод ответа, обработка ошибок |
| `.env.example` | Шаблон `.env` с пустым ключом |
| `README.md` | Описание, установка, запуск, сценарий видео |

## Установка

Используется существующее виртуальное окружение проекта `AICourse/venv`. Новое создавать не нужно.

```bash
cd AICourse
source venv/bin/activate
pip install google-genai      # уже установлен (2.34.0); команда нужна только для чистой установки
```

`python-dotenv` не требуется: `main.py` читает `.env` сам, только средствами стандартной библиотеки.

## Настройка ключа

```bash
cd gemini-task1
cp .env.example .env
# откройте .env и впишите ключ: GEMINI_API_KEY=ваш_ключ
```

Ключ можно получить в [Google AI Studio](https://aistudio.google.com/apikey).
Файл `.env` указан в `.gitignore` и в репозиторий не попадает. Если переменная `GEMINI_API_KEY`
уже задана в окружении, значение из `.env` её не перезаписывает.

## Запуск

```bash
cd gemini-task1
python main.py                                  # запрос по умолчанию
python main.py "Назови три планеты Солнечной системы"   # свой запрос
```

Пример вывода:

```
Модель: gemini-3.5-flash-lite
Запрос: Объясни в двух предложениях, что такое большая языковая модель (LLM).

Ответ модели:
...
```

## Обработка ошибок

| Ситуация | Сообщение | Код выхода |
|----------|-----------|------------|
| Ключ не задан / пустой | `Ошибка: не задан API-ключ GEMINI_API_KEY. ...` | 1 |
| Ошибка API (неверный ключ, лимит, неизвестная модель) | `Ошибка Gemini API (код 400, INVALID_ARGUMENT): ...` | 2 |
| Сеть / таймаут / прочее | `Не удалось выполнить запрос: ...` | 3 |
| Пустой ответ модели | `Модель вернула пустой ответ.` | 4 |

Сообщения об ошибках выводятся в stderr. Ключ в вывод не попадает.

## Сценарий демонстрационного видео (1–2 минуты)

1. **Код (20 с).** Открыть `main.py`.
   *«Это минимальный скрипт на официальном SDK `google-genai`. Ключ не записан в коде: он берётся из переменной `GEMINI_API_KEY`, которая загружается из файла `.env`».*
2. **Шаблон ключа (10 с).** Показать `.env.example`, затем `.gitignore`.
   *«В репозитории есть только шаблон с пустым ключом. Настоящий `.env` игнорируется git».* Содержимое настоящего `.env` на экране не показывать.
3. **Ошибка без ключа (15 с).** Временно убрать ключ, например `mv .env .env.bak`, и запустить `python main.py`.
   *«Без ключа скрипт не падает с трейсбеком, а выводит понятное сообщение и подсказку».* Вернуть файл: `mv .env.bak .env`.
4. **Ошибка API (15 с).** Запустить `GEMINI_API_KEY=invalid python main.py`.
   *«С неверным ключом API возвращает ошибку. Скрипт показывает её код и текст».*
5. **Успешный запрос (30 с).** Запустить `python main.py` и `python main.py "Придумай название для кофейни"`.
   *«Запрос уходит в модель `gemini-3.5-flash-lite`, ответ выводится в консоль. Текст запроса можно передать аргументом».*
6. **Итог (10 с).** *«Первый запрос к LLM через API работает: ключ хранится отдельно от кода, ошибки обрабатываются».*
