# Задача №5 (День 5): версии моделей

Сравнение трёх моделей Gemini — маленькой, средней и флагманской — на одних и тех же задачах
с эталонными ответами. Для каждого ответа измеряются правильность, время, токены и стоимость.
Проект построен по образцу `gemini-task3` и `gemini-task4`: те же повторы, темп запросов,
атомарное сохранение, `--resume` и офлайн-проверки. Файлы Дней 3 и 4 не изменялись.

## Модели

Идентификаторы проверены **06.11.2026** через `client.models.list()` (google-genai 2.34.0):
`python main.py --list-models`. Все три модели поддерживают `generateContent`.

| Роль | Модель | Почему выбрана (по [странице моделей](https://aistudio.google.com/docs/models)) |
|---|---|---|
| Маленькая и дешёвая | `gemini-3.5-flash-lite` | Stable, «the fastest and most cost-effective 3.5 model»; та же модель, что в Днях 3–4 |
| Средняя | `gemini-3.8-flash` | «The most intelligent Flash model»; отмечена как New (без метки Stable/Preview) |
| Флагманская | `gemini-4-argon` | «Our flagship reasoning model» |

Почему не другие модели из `models.list`:
- `gemini-3.5-flash` есть в списке SDK, но её нет ни на странице моделей, ни на странице цен,
  поэтому стоимость посчитать нельзя.
- `gemini-pro-latest` и `gemini-flash-latest` — псевдонимы, которые со временем указывают на
  разные модели. Для воспроизводимости они не подходят.
- `gemini-2.5-pro` и `gemini-2.5-flash` объявлены устаревшими: с 01.12.2026 запросы к ним
  перенаправляются на другие модели.
- `gemini-3.1-pro-preview` — preview-версия, на странице моделей у неё нет описания.
- `gemini-3.6-flash` — Flash предыдущего поколения (Stable) по той же цене. Средней выбрана
  более новая `gemini-3.8-flash`.

## Условия эксперимента (одинаковые для всех моделей)

| Параметр | Значение |
|---|---|
| Промпт | `{вопрос}` + единый формат ответа (Direct из Дня 3) |
| Формат ответа | `response_mime_type="application/json"`, `response_schema={answer, explanation}` |
| `thinking_level` | **LOW** для всех трёх моделей |
| `temperature` | не задаётся (значение по умолчанию 1.0, рекомендовано Google для Gemini 3+) |
| `max_output_tokens` | **8192** для всех трёх моделей (в лимит входят токены рассуждения) |
| Повторов | 1 на пару «задача × модель» (`--repeats N`, чтобы увеличить) |
| Порядок вызовов | задача → три модели подряд (модели чередуются, чтобы нагрузка сервера влияла одинаково) |

**Почему LOW.** По [документации о thinking](https://aistudio.google.com/docs/thinking) у
`gemini-4-argon` есть только `low/medium/high` (по умолчанию medium), а у двух других моделей
также `minimal`. По умолчанию у моделей разные уровни (minimal у Flash-Lite, medium у двух других),
поэтому без явного уровня условия были бы неодинаковыми. LOW — самый низкий уровень, общий для всех трёх.
(`minimal` есть только у `gemini-3.5-flash-lite`; у `gemini-3.8-flash` и `gemini-4-argon` — `low/medium/high`.)

**Почему `max_output_tokens = 8192`.** По документации о thinking этот лимит ограничивает ответ
*вместе с токенами рассуждения*. Если модель упирается в лимит во время рассуждения, уже
сгенерированные thinking-токены всё равно оплачиваются. Без лимита действует максимум модели
(`output_token_limit`: 65 536 у Flash-Lite и 3.8 Flash, 32 768 у Argon), и худший случай полного
запуска ≈ $4.4. С лимитом 8192 максимум конечен (≈ $0.81, см. «Максимальная стоимость»), а обрезка маловероятна:
в Дне 3 даже при HIGH ответ занимал не больше 2 204 токенов. Обрезанный ответ
(`finish_reason = MAX_TOKENS`) отмечается в колонке «Обрезано» и считается неверным.
Лимит меняется в `config.MAX_OUTPUT_TOKENS` (`None` — не передавать).

## Задачи

Шесть задач с эталонами из предыдущих проектов (`tasks.json`). Функции проверки скопированы
из `gemini-task3/validators.py` без изменения логики.

| id | Источник | Эталон | Проверка |
|---|---|---|---|
| `math_bat_ball` | День 3 | 0.05 доллара | все числа ответа, переведённые в доллары («5 центов» → 0.05), равны ровно 0.05 |
| `logic_syllogism` | День 3 | да | есть «да/следует», нет «нет/не следует» |
| `combinatorics_digits` | День 3 | 24 | ровно одно различное число, равное 24 |
| `algorithm_loop` | День 3 | 14 | ровно одно различное число, равное 14 |
| `order_logic` | День 3 | D, A, B, C | последовательность букв совпадает точно |
| `days_count` | День 4 | 107 | ровно одно различное число, равное 107 (проверено через `datetime`) |

Правильность определяется только программной проверкой, самооценка модели не учитывается.
Ответ, который не разобрался как JSON или не прошёл схему, считается неверным.

## Что измеряется

| Метрика | Источник |
|---|---|
| Правильность | `validators.py` |
| Время, с | длительность успешного вызова `generate_content`, без пауз темпа и повторов |
| Входные токены | `usage_metadata.prompt_token_count` |
| Выходные токены | `candidates_token_count + thoughts_token_count` (так их тарифицирует Google) |
| Всего токенов | `usage_metadata.total_token_count` |
| Стоимость, $ | `(вход − кэш) × цена_входа + кэш × цена_кэша + выход × цена_выхода`, цены за 1M |

Токены рассуждения (`thoughts_token_count`) входят в выходные: на странице цен строка называется
«Output price (including thinking tokens)». Отдельно они показаны в скобках в колонке «Выходные».

Если API не вернул `usage_metadata`, стоимость записывается как `null` с причиной в `cost_note`
и не подменяется нулём. Сумма по модели тогда помечается «*» (нижняя оценка).

## Тарифы

Standard (paid tier), USD за 1 000 000 токенов. **Дата проверки: 06.11.2026.**
Источник: <https://ai.google.dev/gemini-api/docs/pricing> (перенаправляет на
<https://aistudio.google.com/docs/pricing>). Выходная цена включает токены рассуждения
(«Output price (including thinking tokens)»).

| Модель | Период | Вход | Выход | Бесплатный уровень |
|---|---|---|---|---|
| `gemini-3.5-flash-lite` | без ограничения | $0.30 | $2.50 | есть |
| `gemini-3.8-flash` | по 31.12.2026 | $0.75 | $3.75 | есть |
| `gemini-3.8-flash` | с 01.01.2027 | $1.50 | $7.50 | есть |
| `gemini-4-argon` | по 30.11.2026 | $2.00 | $10.00 | **нет** |
| `gemini-4-argon` | с 01.12.2026 | $4.00 | $20.00 | **нет** |

Цена выбирается **по дате запроса**: при запуске после 30.11.2026 флагман считается по $4/$20.

Ограничения расчёта:
- Если ключ работает на бесплатном уровне, Google не списывает деньги за Flash-Lite и Flash.
  Тогда в таблице — стоимость, которую запрос **стоил бы** на Standard paid tier.
- У `gemini-4-argon` бесплатного уровня нет. Для него нужен проект с подключённым billing,
  иначе API вернёт ошибку: скрипт запишет её и не будет отправлять остальные задачи этой модели.
- Неявное кэширование учитывается по `cached_content_token_count`. Промпты здесь короткие,
  поэтому кэша скорее всего не будет.
- Расчёт по прайсу ≈ счёт Google. Точную сумму показывает только Billing в Google Cloud Console.

## Файлы

- `main.py` — запуск: вызовы API, повторы, логирование, сохранение, CLI.
- `config.py` — модели, условия генерации, темп и повторы, тарифы с источниками.
- `tasks.json` — 6 задач с эталонами; `tasks.py` — загрузка и привязка функций проверки.
- `validators.py` — разбор JSON и проверки (копия из Дня 3 + задача из Дня 4).
- `pricing.py` — тарифы по дате и расчёт стоимости.
- `report.py` — итоговая таблица, сравнения, `summary.*`.
- `offline_checks.py` — проверки без сети на поддельном клиенте.
- `results/run_N/` — результаты запуска:
  - `results.json` / `results.csv` — по строке на каждый ответ (в JSON есть журнал попыток);
  - `summary.json` / `summary.csv` / `summary.md` — итоговая таблица и сравнения;
  - `run_meta.json` — модели, конфигурация запроса, тарифы, версия SDK;
  - `run.log` — лог запуска;
  - `superseded.json` — неудачные записи, которые заменил `--resume`.

## Запуск

```bash
cd ~/work/AICourse/gemini-task5
export GEMINI_API_KEY="ваш_ключ"          # ключ нигде не печатается и не сохраняется

../venv/bin/python offline_checks.py      # проверки без API
../venv/bin/python main.py --list-models  # доступность моделей (метаданные, без генерации)
../venv/bin/python main.py --dry-run      # план, промпты, тарифы, оценка цены; без API
../venv/bin/python main.py --pilot        # 1 задача × 3 модели = 3 платных вызова
../venv/bin/python main.py --full         # 6 задач × 3 модели = 18 платных вызовов
../venv/bin/python main.py --resume run_N # повторить неудачные вызовы
../venv/bin/python main.py --report run_N # пересобрать таблицу из сохранённых результатов
```

Перед `--pilot`, `--full` и `--resume` скрипт показывает план и оценку цены, а затем спрашивает
подтверждение. Флаг `--yes` отключает вопрос.

### Максимальная стоимость `--full` (18 запросов, тарифы на 06.11.2026)

Считается как ≤ 500 входных токенов (с запасом: самый длинный промпт — 238 символов) плюс весь
лимит выхода 8192 токена (включая thinking) на каждый запрос:

| Модель | Максимум за запрос | × 6 задач |
|---|---|---|
| `gemini-3.5-flash-lite` | $0.0206 | $0.1238 |
| `gemini-3.8-flash` | $0.0311 | $0.1866 |
| `gemini-4-argon` | $0.0829 | $0.4975 |
| **Итого** | | **≤ $0.81** |

- **≤ $0.81** — если оплачивается одна попытка на запрос. Ответы с ошибкой API (503, 429)
  без генерации не тарифицируются.
- **≤ $2.42** — абсолютный худший случай: оплачены все 3 попытки, например при клиентских таймаутах
  после того, как сервер уже сгенерировал ответ.
- **≈ $0.10** — типичная оценка (150 входных + 1000 выходных токенов на запрос). Это не предел.
- При запуске после 30.11.2026 цена Argon удваивается, и максимум растёт до ≈ $1.31.

Те же числа печатает `--dry-run`.

## Надёжность

- Интервал между началами любых двух запросов — не меньше 13 с (бесплатный тариф: 5 запросов в минуту).
- Повторы при 429/500/502/503/504 и сетевых таймаутах: до 3 попыток на вызов, паузы 15 и 30 с.
  Для 429 учитывается подсказка сервера «retry in Ns» (не больше 60 с).
- 429 из-за дневной квоты, 403 и 404: оставшиеся задачи этой модели не отправляются,
  отмечаются как `skipped`, остальные модели продолжают работу.
- 401 (неверный ключ): эксперимент останавливается.
- После каждого ответа все файлы перезаписываются атомарно. Ctrl+C сохраняет полученное,
  продолжение — `--resume run_N`.
- Ключ берётся только из `GEMINI_API_KEY`. Фильтр логов и запись результатов заменяют его
  на `***`, если он попадёт в текст ошибки. Это проверяет `offline_checks.py`.

## Ограничения

- **Эффект потолка.** В Дне 3 `gemini-3.5-flash-lite` решила все 5 задач на 100% даже при
  MINIMAL. Скорее всего, все три модели снова наберут 6/6, и тогда разница будет видна только
  в цене, токенах и времени. Вывод о точности на таком наборе сделать нельзя.
- **Мало задач:** одна задача меняет точность на 16,7 п.п. По умолчанию каждая задача решается один раз.
- **Задача `order_logic` подсказывает ответ:** порядок в условии совпадает с эталоном.
- **Время зашумлено** нагрузкой серверов (в Дне 3 были 503/504 и ответы до 80 с), поэтому
  токены и стоимость надёжнее времени.
- **thinking_level=LOW** одинаков для всех моделей, но это не настройка «по умолчанию» для
  каждой из них: флагман по умолчанию работает на medium и мог бы ответить иначе.
